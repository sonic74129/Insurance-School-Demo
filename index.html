Demo 说明书 · 一步一步做

可拖标题移动、拖边缘或角落调宽高。右上角横线最小化、方框最大化；重叠方框还原放大前窗口。小屏自适应。从右下角继续原步骤；阅读位置不代表业务进度，刷新后重置。

先准备，再选一条流程

  1. 如果拿到 ZIP，先完整解压，用 Edge 或 Chrome 打开里面的 index.html。单个 HTML 文件可以直接打开，不需要安装开发工具。
  2. 在旁边的操作页面登录；小屏可先收起指南，再从右下角展开继续。若已登录，先点右上角「登出」。登录页如有「啟用v2合成場景」，点它；没有就跳过。无需输入密码。
  3. 在说明书的「你要做什么？」选择「① 巡检与整改」，点「带我到这一步 · 箭头提示」。需要换角色时先请你确认；成功定位后指南收起到右下角，箭头标出要点的按钮或输入框，不会替你提交。看到完成标志后从右下角展开，再点「下一步」。

怎么换角色：点右上角「登出」，找到指定姓名的卡片，点卡片里的「以此角色進入」。主管部门选「省級教育監管員」；第三方选「巡檢服務專員」；学校选「青禾中學安全管理員」；保险公司选「保險核保經理」。

有旧进度也能继续：在上方步骤下拉框选择还没做的步骤。不确定进度时先看「找不到按钮」，不要急着重设。重设会清除当前浏览器的演示操作。

当前角色：主管部门 · 省級教育監管員

派一张青禾主校区巡检任务

  1. 在操作区，若已登录其他角色，先「登出」；在「省級教育監管員」卡片点「以此角色進入」。
  2. 点左侧「平台服務管理（演示代辦）」。找到状态为「生效」的秋季计划，不用新建计划，也不用先买保险。
  3. 在该计划的「計畫授權校區」选「青禾中學主校區」，点一次「按計畫派單」。
  4. 点左侧「校園巡檢與整改」，找到「青禾中學主校區」任务卡，记下标题里的完整 TASK-数字 编号。

完成标志：这张任务卡显示「待接單」。后面始终找这个编号，不再派单。PLAN 是计划，RPT 是报告，都不是任务编号。

已有青禾主校区任务？不要重复派单，直接跳到符合任务状态的步骤。

换角色：第三方 · 巡檢服務專員

接下刚才的任务

  1. 在操作区，点右上角「登出」。在「巡檢服務專員」卡片点「以此角色進入」。
  2. 点左侧「巡檢任務」，找标题带刚才 TASK 编号的「青禾中學主校區」卡片，不要选背景学校。
  3. 在这张卡片点「接受巡檢任務」。

完成标志：任务变成「執行中」，下方出现22项检查表。此时结果是「待錄入」，不是已经检查完了。

保持第三方角色 · 同一张任务卡

填入这次演示用的检查结果

  1. 在22项检查表上方，点「載入合成示例（覆蓋草稿前確認）」。
  2. 浏览器弹出确认框时，点确定。此操作会覆盖这张任务的检查草稿，只用于合成演示。
  3. 看一下 C02：结果应为「未檢查」；C05、C13 是这次要处理的两项隐患，先不要改它们。

完成标志：检查表有了不同结果，不是全部合格。C02故意留作下一段的“补查”演示。

保持第三方角色 · 同一张任务卡

提交第一版报告

  1. 滚到这张任务的22项检查表最底部。
  2. 点「提交結構化報告」，不要只点「保存草稿」。

完成标志：任务显示「報告已提交」，出现「查看報告… v1」和 C05、C13 两张隐患卡。v1就是第一版；C02未检不会被当成已完成。

换角色：主管部门 · 省級教育監管員

试一次验收：看到未检拦截是正常的

  1. 在操作区，「登出」；在「省級教育監管員」卡片点「以此角色進入」。点左侧「校園巡檢與整改」，找同一 TASK 编号。
  2. 在任务内找「主管部門：驗收此現場報告」。第1步下拉选「通過現場及報告驗收」，第2步理由保留预填内容。
  3. 点「第3步：提交現場報告驗收」，留意页面短暂出现的提示。

应看到：「仍有未檢／缺失，請補查並更正報告後再完整驗收。」这是演示要展示的拦截，不是操作错了。继续下一步补查，不用反复点验收。

换角色：第三方 · 巡檢服務專員

补上 C02 的检查结果

  1. 在操作区，「登出」；用「巡檢服務專員」进入。点左侧「巡檢任務」，找到同一 TASK 编号。
  2. 点「更正／補查並出新版本」。在展开的表单找到「C02 · 雨棚外牆吊頂及懸掛物可見鬆脫」。
  3. 把 C02 的「檢查結果」改成「合格」。
  4. 把 C02 的「觀察事實／不適用或未檢原因及補查安排」替换为下面这句合成描述，其他项目不改。

合成補查：雨棚指定地面目視點位完成，未見可見鬆脫，限本次觀察。

完成标志：C02表单已改好。还没提交，下一步要提交新版本。

保持第三方角色 · 同一张任务卡

提交第二版报告

  1. 滚到检查表最底部，点「提交結構化報告」。
  2. 在任务卡下方找到「查看報告… v2」。旧版应保留在「歷史報告… v1」中。

完成标志：出现v2（第二版），C05、C13仍各只有一张隐患卡。补查不会覆盖旧报告，也不会重复生成隐患。

换角色：主管部门 · 省級教育監管員

验收补查后的报告

  1. 在操作区，「登出」；用「省級教育監管員」进入。点左侧「校園巡檢與整改」，找到同一 TASK 编号。

完成标志：卡片显示「現場交付：已驗收」，验收表单消失。这里只确认报告交付；两项隐患还没解决，资金也没有支付。

如果已经显示「已驗收」，本步不用再做，直接下一步。

完成标志：提示「已記錄報告收悉。」按钮消失。收悉只是“收到了”，不表示学校承认法律责任。

保持学校角色 · 同一张任务卡

先确认 C05 由谁、何时整改

  1. 在任务卡的报告区域下方，找到标题含「／C05」的隐患卡，不是报告表格里的C05那一行。
  2. 这张卡片内的主责、协同、期限、临时措施已有合成示例，保留预填内容。
  3. 点这张 C05 卡片里的「確認責任及期限」。

完成标志：C05从「待確認」变为「待整改」，出现「提交整改待複查」按钮。这里记录整改分工，不是判定保险或法律责任。

保持学校角色 · 同一张任务卡

再确认 C13 由谁、何时整改

  1. 找到标题含「／C13」的另一张隐患卡。
  2. 保留这张卡片内预填的主责、协同、期限和临时措施。
  3. 点 C13 卡片里的「確認責任及期限」。

完成标志：C13变为「待整改」，出现「專業轉介與合成文件元資料」。下一步先补专业结论，不要急着提交整改。

保持学校角色 · C13 隐患卡

给 C13 记录专业结论

  1. 在 C13 卡片点「專業轉介與合成文件元資料」，展开表单。
  2. 把「轉介狀態」改为「已取得結論」。
  3. 专业单位、含C13的核查范围、文件索引保留合成预填值；「文件結論（不自動銷號）」保持「符合本次處置要求」。
  4. 点「記錄專業轉介」。

完成标志：C13的「專業」一行显示「已取得結論／符合本次處置要求」。这不等于已整改或已销号。

保持学校角色 · C05 隐患卡

提交 C05 的整改资料

  3. 点 C05 卡片里的「提交整改待複查」。

完成标志：C05变成「待複查」。学校提交的是整改资料，要等第三方复查，不是自行销号。

保持学校角色 · C13 隐患卡

提交 C13 的整改资料

  1. 回到标题含「／C13」的隐患卡，确认「專業」一行已有符合要求的结论。
  2. 保留预填的整改措施和整改证据索引。
  3. 点 C13 卡片里的「提交整改待複查」。

完成标志：C05、C13两张卡片现在都显示「待複查」。下一步换第三方。

换角色：第三方 · 巡檢服務專員

  2. C05、C13两张隐患卡都显示「已銷號」。

找不到按钮，先对照这里

  • 不知道接着做哪步：看同一TASK任务的状态。「待接單」从巡检第2步继续；「執行中」且未填结果从第3步继续；已提交v1且C02未检从第5步继续；已提交v2但未验收从第8步继续；「現場交付：已驗收」从第9步学校收悉继续。已经做过的确认、整改或复查可跳过。
  • 找不到验收区：必须登录主管部门，且当前报告已提交。若已显示「已驗收」，验收区隐藏是正常的；若第三方只保存了草稿，先完成提交。
  • 找不到学校或第三方的按钮：检查右上角登录角色和TASK编号；学校先确认责任才出现整改表单，第三方等学校提交后才出现复查表单。C13还需要匹配且符合要求的专业结论。
  • 复查次数用完：默认计划每项上限1次，退回和证据不足也计次。若想演示多轮，须在派单前由主管部门新建计划，把「每隱患複查上限」设为3，建立草稿、批准、生效后再派单；不要对旧任务反复提交。
  • 想从头重来：在操作区，右上角「登出」，登录页点「重設演示資料」并确认。会清除当前v2操作，旧v1保留。任务编号可能变化，重新记录；阅读步骤请手动选回第1步。
